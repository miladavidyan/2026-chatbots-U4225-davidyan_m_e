## 1. Описание задачи

**Цель работы** — расширить Telegram-бота Marketing Metrics Bot, добавив получение и обработку данных из CSV- и Excel-файлов и смысловой анализ клиентских отзывов с помощью языковой модели.

В версии 2.0 бот рассчитывал **12 маркетинговых метрик** (ER, ERR, CTR, CPC, CPM, ROMI, CR, CPA, CPL, CAC, ROAS, AOV), анализировал показатели рекламной кампании, содержал справочник и сохранял историю расчетов. При этом он работал преимущественно с числовыми данными, вводимыми вручную.

**Проблема:** клиентские отзывы содержат важную информацию об ожиданиях, удовлетворенности и проблемах покупателей, но их ручное прочтение и систематизация занимают время. Было решено объединить в одном инструменте количественную маркетинговую аналитику и анализ текстовых отзывов.

**Выбранные интеграции:**

1. **Файлы CSV и XLSX** — загрузка отзывов и, при наличии, оценок; расчет описательной статистики.
2. **Внешний LLM API** — интерпретация текстов, выявление положительных и отрицательных впечатлений, формирование рекомендаций.

## 2. Подготовка данных

Бот принимает документы `.csv` и `.xlsx`. Обязателен столбец с текстом отзыва; оценки не обязательны.

| Поле | Допустимые названия | Назначение |
|---|---|---|
| Текст | `review`, `text`, `отзыв`, `текст` | Обязательное содержимое отзыва |
| Оценка | `rating`, `оценка` | Необязательная оценка от 1 до 5 |

Для тестирования использовались отзывы о заведении общественного питания. Один тестовый файл содержал **5 отзывов без числовых оценок**. Бот корректно определил количество записей и сообщил, что статистика оценок недоступна.

Данные для одного пользователя сохраняются отдельно от данных других пользователей. Повторная загрузка заменяет предыдущий набор отзывов этого пользователя, но не изменяет историю расчетов метрик.

## 8. Трудности и решения

**Подключение к учебному шлюзу.** Сначала проверили доступ с помощью отдельного скрипта, затем настроили клиент OpenAI-совместимого API в самом боте. Реальный ключ сохранили в `.env`.

**Неодинаковые входные файлы.** Добавили проверку расширения, размера, имен колонок, содержимого и кодировки CSV. Оценки сделали необязательными.

**Ограниченный лимит LLM Gateway.** Установили ограничения на файлы и объем текста, передаваемый модели; статистика считается локально и не расходует запросы к LLM.

**Недостаточно удобный первый отчет.** После проверки версии 3.0 переработали сценарий и промпт: пять стабильных блоков, отдельные сообщения и более конкретные рекомендации.

**Риск галлюцинаций модели.** Требуем дословные цитаты, а в Python проверяем их наличие в исходных отзывах. Такая проверка подтверждает подлинность цитаты, но сама по себе не гарантирует корректность любой интерпретации — поэтому в отчете остаются оговорки об ограничениях анализа.


## 9. Реализация

### 9.1. Как работает интеграция

В итоговой версии используется следующая последовательность:

1. **Telegram:** пользователь открывает «Анализ отзывов» и отправляет CSV/XLSX как документ.
2. **Python:** бот скачивает файл, проверяет его размер и формат, находит столбец с отзывами и извлекает данные.
3. **Локальное хранение:** отзывы сохраняются в `reviews.json` по Telegram ID пользователя. История калькулятора остается отдельно в `history.json`.
4. **Статистика:** количество отзывов и данные по оценкам вычисляются на Python **без обращения к LLM**.
5. **AI-анализ:** по нажатию кнопки бот собирает допустимое количество отзывов и отправляет их через `AsyncOpenAI` в FTMI Gateway.
6. **Проверка:** Python разбирает структурированный JSON-ответ и исключает пункты, цитаты которых не удалось подтвердить по исходным отзывам.
7. **Вывод:** бот формирует пять тематических сообщений в Telegram. Загруженные отзывы после анализа сохраняются.

**Ограничения реализации:** максимальный размер файла — **3 МБ**, до **500 строк** в документе, до **80 отзывов** и **24 000 символов текста** за один AI-анализ. Эти ограничения относятся к текущей учебной реализации, а не к возможностям модели в целом.

**2. Чтение CSV и XLSX**

```python
def parse_reviews(filename, content):
    ext = Path(filename).suffix.lower()
    if ext not in ('.csv', '.xlsx'):
        raise ValueError('Поддерживаются только файлы .csv и .xlsx.')
    if not content or len(content) > MAX_UPLOAD_BYTES:
        raise ValueError('Файл пустой или превышает лимит 3 МБ.')
    if ext == '.csv':
        text = None
        for encoding in ('utf-8-sig', 'cp1251'):
            try:
                text = content.decode(encoding)
                break
            except UnicodeDecodeError:
                continue
        # Далее CSV читается через csv.reader.
    else:
        # Для Excel используется openpyxl.load_workbook.
        workbook = load_workbook(
            io.BytesIO(content), read_only=True, data_only=True
        )
```

*В этом фрагменте опущены строки обработки заголовков, строк и закрытия файла; полный метод в рабочем коде выполняет эти проверки.*

**3. Передача отзывов языковой модели**

```python
client = AsyncOpenAI(
    api_key=GATEWAY_KEY,
    base_url=GATEWAY_URL,
    timeout=60.0,
    max_retries=1
)
payload = [
    {'id': i + 1, 'text': r['text'], 'rating': r.get('rating')}
    for i, r in enumerate(rows)
]
response = await client.chat.completions.create(
    model=GATEWAY_MODEL,
    messages=[
        {'role': 'system', 'content': SYSTEM_ANALYSIS},
        {'role': 'user', 'content': json.dumps(payload, ensure_ascii=False)}
    ],
    temperature=0.2,
)
```

`SYSTEM_ANALYSIS` содержит правила и схему аналитического отчета. Исходные отзывы отправляются отдельным сообщением как JSON с идентификаторами, текстами и необязательными оценками.

**4. Проверка дословных цитат по исходным отзывам**

```python
for ident in ids:
    if (
        type(ident) is int
        and 1 <= ident <= len(rows)
        and quote in rows[ident - 1]['text']
        and ident not in exact_ids
    ):
        exact_ids.append(ident)

if not exact_ids:
    continue
```

Так бот исключает из структурированного отчета пункты, для которых не удалось подтвердить цитату в указанном отзыве.

**5. Создание пяти сообщений вместо одного длинного отчета**

```python
report_messages = format_ai_report(result, rows)

for report_part in report_messages:
    await send_long(message, report_part)
```

Функция `format_ai_report()` формирует пять разделов в заданном порядке. `send_long()` дополнительно учитывает ограничение Telegram на длину сообщения.

| `json` | Хранение данных и разбор структурированного ответа модели | Простой формат для учебного проекта |
| `io`, `pathlib` | Работа с содержимым и путями файлов | Встроенные средства Python |
| `collections.Counter` | Подсчет оценок по категориям | Удобная обработка частот |
| `datetime`, `threading`, `logging`, `math`, `os` | Время, синхронизация записи, журналы, проверки и окружение | Стандартные средства Python |

Таким образом, статистика отзывов вычисляется локально, а LLM используется только для задач, требующих смысловой интерпретации текста.

## 11. Выводы

В ходе лабораторной работы Marketing Metrics Bot был расширен от калькулятора маркетинговых показателей до инструмента, объединяющего **количественную аналитику и работу с текстовыми клиентскими данными**.

- Реализовано хранение отзывов отдельно от истории расчетов.
- Проведены две итерации улучшения: от первоначального AI-анализа версии 3.0 к структурированному отчету версии 3.1.
- Отчет разделен на пять смысловых блоков, а рекомендации связаны с конкретными отзывами и способами проверки.

**Чему научились:** формулировать требования к интеграции через промпты, подключать файлы и OpenAI-совместимый API, разделять алгоритмические расчеты и задачи LLM, проверять результаты модели и улучшать продукт после пользовательского тестирования.

**Возможные следующие улучшения:** анализ больших массивов по частям, точный автоматизированный подсчет тематических упоминаний, сравнение отзывов за разные периоды, экспорт отчетов и размещение бота на сервере для работы 24/7.

**Итог:** лабораторная работа продемонстрировала, как с помощью итеративной LLM-генерации кода можно расширить готового Telegram-бота интеграцией с файлами и внешней языковой моделью и сделать аналитические результаты более полезными для бизнеса.
