## 1. Описание задачи

Цель проекта — разработать Telegram-бота, который автоматизирует расчет базовых маркетинговых показателей и помогает пользователям интерпретировать полученные результаты.

### 1.1. Решаемая проблема

В повседневной работе маркетологи используют множество количественных показателей для оценки эффективности контента, рекламных кампаний и продаж. Для их расчета необходимо знать соответствующие формулы, правильно определять исходные данные и выполнять вычисления.

Использование электронных таблиц или ручных расчетов не всегда удобно, особенно когда требуется быстро рассчитать один или несколько показателей.

**Marketing Metrics Bot** решает эту задачу, предоставляя пользователю возможность рассчитывать маркетинговые метрики непосредственно в Telegram.

### 1.2. Обоснование выбора задачи

Данная задача была выбрана по следующим причинам:

- **Практическая применимость.** Расчет маркетинговых показателей является распространенной задачей в маркетинге, рекламе и SMM.
- **Возможность автоматизации.** Большинство базовых метрик рассчитываются по математическим формулам и не требуют сложных алгоритмов.
- **Простота взаимодействия.** Telegram позволяет организовать последовательный ввод данных с помощью сообщений и интерактивных кнопок.
- **Возможность развития.** Базовый калькулятор можно постепенно расширять дополнительными показателями и аналитическими функциями.

Для разработки программного кода использовалась LLM — ChatGPT. При этом сам Telegram-бот выполняет расчеты с помощью Python и не требует подключения языковой модели.

## 2. Промпт-инжиниринг и процесс разработки

Разработка проходила итеративно. Сначала был создан минимально работоспособный продукт (MVP), после чего его функциональность была расширена на основе оценки первой версии.

### 2.1. Исходный промпт: первая версия бота

Первоначальная задача заключалась в разработке простого Telegram-калькулятора маркетинговых показателей.

**Исходный промпт (восстановленная формулировка):**

> Создай Telegram-бота Marketing Metrics Bot на Python с использованием библиотеки python-telegram-bot.
>
> Бот должен рассчитывать шесть базовых маркетинговых показателей: ER, ERR, CTR, CPC, CPM и ROMI.
>
> Пользователь выбирает показатель, вводит необходимые числовые значения и получает результат расчета с формулой и кратким объяснением.
>
> Реализуй удобное меню с кнопками, возможность отмены расчета и сохранение истории в локальном JSON-файле отдельно для каждого пользователя.
>
> Добавь обработку некорректного ввода и ошибок, комментарии в коде и инструкцию по запуску на Windows.
>
> Используй библиотеку python-telegram-bot. Для конфигурации используй файл `.env` и переменную `TELEGRAM_BOT_TOKEN`.
>
> Создай файлы `bot.py`, `requirements.txt`, `README.md` и `.env.example`.
>
> Бот должен работать без подключения внешних сервисов искусственного интеллекта.

### 2.2. Результат первой итерации

В первой версии были реализованы следующие функции:

- Расчет шести показателей: ER, ERR, CTR, CPC, CPM, ROMI.
- Выбор необходимого показателя через интерактивные кнопки.
- Пошаговый ввод исходных данных.
- Автоматический расчет результата с отображением формулы.
- Сохранение истории вычислений в JSON.
- Просмотр истории и удаление записей с подтверждением.
- Команды для запуска, получения справки и отмены текущего расчета.

После генерации кода были созданы файлы проекта, настроен токен Telegram-бота через `.env` и выполнен запуск из командной строки Windows (CMD).

Первая версия представляла собой функциональный калькулятор, однако имела ограниченный набор показателей. Кроме того, по мере расширения функциональности потребовалась более удобная организация меню.

### 2.3. Вторая итерация: расширение функциональности

После тестирования первой версии было принято решение превратить калькулятор отдельных метрик в более универсальный инструмент для маркетолога.

Для этого были сформулированы четыре направления улучшений.

#### 2.3.1. Расширение набора показателей

К шести первоначальным метрикам добавлены еще шесть:

| Метрика | Назначение |
|---|---|
| CR | Коэффициент конверсии |
| CPA | Стоимость целевого действия |
| CPL | Стоимость привлечения лида |
| CAC | Стоимость привлечения клиента |
| ROAS | Отношение рекламной выручки к расходам на рекламу |
| AOV | Средний чек |

Таким образом, общее количество показателей увеличилось с **6 до 12**.

#### 2.3.2. Изменение структуры меню

В первой версии пользователь выбирал показатель из общего списка. Во второй версии была введена группировка метрик по тематическим разделам:

- SMM-метрики.
- Реклама.
- Продажи.

Помимо категорий, в главное меню были вынесены анализ рекламной кампании, история расчетов и справочник.

#### 2.3.3. Разработка функции анализа рекламной кампании

Была добавлена возможность рассчитывать несколько взаимосвязанных метрик за один сценарий взаимодействия.

Пользователь последовательно вводит:

1. Рекламные расходы.
2. Количество показов.
3. Количество кликов.
4. Количество конверсий.
5. Полученную выручку.

На основании этих данных бот рассчитывает **CTR, CPC, CPM, CR, CPA и ROAS**, а также формирует краткие пояснения.

#### 2.3.4. Добавление справочника маркетолога

Для каждого показателя реализована справочная информация: определение, формула расчета и особенности интерпретации.

Это расширило назначение бота: помимо вычислений, он стал выполнять образовательную и справочную функцию.

## 3. Стек технологий

Для реализации проекта использовались следующие технологии:

| Технология | Назначение |
|---|---|
| Python 3.13 | Основной язык программирования |
| python-telegram-bot 22.x | Взаимодействие с Telegram Bot API |
| python-dotenv | Загрузка токена из файла `.env` |
| json | Сохранение истории расчетов |
| pathlib | Работа с путями к файлам |
| datetime | Фиксация даты и времени вычислений |
| Telegram Bot API | Обмен сообщениями и обработка команд |
| ChatGPT | Генерация и доработка программного кода |

### 3.1. Обоснование выбора технологий

**Python** был выбран благодаря простоте синтаксиса, доступности библиотек и возможности быстро реализовать необходимую математическую логику.

**python-telegram-bot** позволяет организовать обработку сообщений, команд и нажатий кнопок, не реализуя взаимодействие с Telegram API вручную.

**JSON** используется для локального хранения истории. Для учебного MVP такой подход позволяет избежать настройки отдельной базы данных.

**python-dotenv** обеспечивает хранение Telegram-токена отдельно от основного исходного кода.

**ChatGPT** применялся на этапе проектирования, генерации кода, разработки новых функций и подготовки инструкций по запуску. AI не участвует в вычислениях при использовании готового бота.

### 3.2. Структура проекта

Основные файлы проекта:

| Файл | Назначение |
|---|---|
| `bot.py` | Программная логика бота |
| `requirements.txt` | Список зависимостей |
| `README.md` | Инструкция по установке и запуску |
| `.env.example` | Шаблон конфигурации |
| `.env` | Локальное хранение токена Telegram-бота |
| `history.json` | Локальная история вычислений |

Файл `.env` содержит конфиденциальную информацию и не должен публиковаться в открытом репозитории GitHub.

## 5. Трудности и способы их решения

### 5.1. Выбор архитектуры бота

На этапе проектирования было важно определить, какие задачи требуют интеллектуальной обработки, а какие могут быть решены стандартными алгоритмами.

Для маркетингового калькулятора было принято решение использовать математические формулы без подключения LLM API.

Это позволило исключить дополнительные зависимости, связанные с доступом к внешним AI-сервисам, и упростить запуск проекта.

### 5.2. Ограниченность первой версии

Первая версия рассчитывала только шесть маркетинговых метрик. Для более широкого практического применения этого набора оказалось недостаточно.
<img width="1022" height="594" alt="image" src="https://github.com/user-attachments/assets/e202ad14-035c-47b0-8d3c-57ff445f20d0" />


**Решение:** набор показателей был расширен до 12, а метрики сгруппированы по направлениям применения.

### 5.3. Удобство интерфейса

При увеличении количества показателей единый список выбора становился менее удобным.

**Решение:** было переработано главное меню. Показатели распределили по категориям, а дополнительные функции вынесли в отдельные разделы.

### 5.4. Обновление без потери данных

При переходе на версию 2.0 возникла задача сохранить настройки и историю вычислений, не нарушив работу предыдущей версии.

**Решение:** новая версия была создана в отдельной папке. Файлы конфигурации и истории переносились копированием, а предыдущая версия сохранялась как резервная.

### 5.5. Корректировка пользовательских сообщений

В приветственном сообщении второй версии присутствовала техническая информация об отсутствии AI API. Она не представляла ценности для конечного пользователя.

**Решение:** было принято решение убрать техническое пояснение из приветствия, сохранив описание основных возможностей бота.

### 5.6. Ограничения локального запуска

При тестировании выяснилось, что бот работает только при активном Python-процессе на компьютере. Закрытие CMD обычно приводит к завершению программы.

**Возможное дальнейшее решение:** размещение бота на облачном сервере для круглосуточной доступности.

Для выполнения лабораторной работы использовался локальный запуск.

### 6.4. Приобретенные навыки

В ходе работы были освоены базовые принципы создания Telegram-ботов, настройки Python-окружения, использования переменных окружения, работы с JSON и взаимодействия с LLM при разработке программного обеспечения.

Особое внимание было уделено **итеративному промпт-инжинирингу**: постановке задачи на естественном языке, уточнению требований, оценке промежуточного результата и последовательной доработке продукта.

**Итог:** лабораторная работа продемонстрировала возможность разработки и развития прикладного программного продукта с помощью LLM без самостоятельного написания кода и без необходимости интегрировать искусственный интеллект в сам продукт.
