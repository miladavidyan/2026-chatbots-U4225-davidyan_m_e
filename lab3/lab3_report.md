# Лабораторная работа № 3. Деплой и развитие Marketing Metrics Bot

**Проект:** Marketing Metrics Bot (Dollars & Drama)  
**Итоговая версия:** 3.2  
**Стек:** Python, Telegram Bot API, GitHub, Railway, FTMI Gateway  
**Репозиторий:** [marketing-metrics-bot](https://github.com/miladavidyan/marketing-metrics-bot)  
**Telegram-бот:** @itmoftmi_dmee_bot

## 1. Описание деплоя

**Цель:** разместить Telegram-бота в облаке, протестировать его с пользователями и улучшить по итогам тестирования.

Для размещения выбран **Railway** с подключением репозитория **GitHub**. Бот использует **Long Polling**: самостоятельно получает обновления от Telegram, поэтому отдельный публичный URL и настройка Webhook не нужны. Railway позволяет запускать Python-приложение, хранить секреты в переменных окружения и автоматически развертывать обновления.

Бот рассчитывает 12 маркетинговых метрик, анализирует рекламные кампании, хранит историю расчетов и выполняет статистический и AI-анализ отзывов из CSV/XLSX.

## 4. Анализ обратной связи

**Что понравилось:** доступность бота в Telegram, возможность быстро выполнять расчеты, отсутствие технических затруднений при тестировании.

**Главная проблема:** числовой результат не всегда понятен без контекста. Например, ER = 25% не означает, что ровно 25% уникальных подписчиков проявили активность: один человек может совершить несколько взаимодействий.

## 5. Улучшение и повторная проверка

В версии **3.2** после расчета каждой из **12 метрик** появился блок **«📊 Как интерпретировать результат»**. Он объясняет смысл значения и ограничения его использования. Дополнительных вопросов к пользователю и новых AI-запросов не требуется.

**Примеры:**

- **ER:** число взаимодействий относительно подписчиков; не равно доле уникальных вовлеченных людей.
- **AOV:** средний чек; его рост не гарантирует роста прибыли.
- **ROAS:** рекламная выручка относительно затрат на рекламу; не равен прибыли.
- **ROMI:** результат зависит от полноты учета расходов и корректной атрибуции выручки.

Обновленный `bot.py` загружен в GitHub. Railway автоматически выполнил новый деплой со статусом **ACTIVE / Deployment successful**. Остальные функции и хранение истории сохранены.

## 6. Промпты для работы с LLM

Ниже приведены **восстановленные формулировки промптов по фактическим задачам проекта**, а не дословные копии всех ранее отправленных запросов. Они показывают, как можно было использовать LLM на соответствующих этапах.

### Промпт 1. Подготовка бота к Railway

```text
У меня есть Telegram-бот на Python с python-telegram-bot, который сейчас
запускается локально через Long Polling. Подготовь его для Railway, не меняя
основную функциональность. Добавь requirements.txt, railway.toml,
.env.example, .gitignore и краткую инструкцию по деплою.
Токены и API-ключи читай из переменных окружения, не помещай их в репозиторий.
Сохрани Long Polling: Webhook и публичный веб-сервер не нужны.
```

### Промпт 2. Постоянное хранение истории

```text
Измени существующий bot.py так, чтобы локально JSON-файлы с историей
расчетов и отзывами сохранялись рядом с кодом, а на Railway — в каталоге,
заданном переменной DATA_DIR=/data. Не меняй формулы, меню, команды
и AI-анализ. Проверь, что изменение совместимо с Railway Volume.
```

### Промпт 3. Интерпретация результатов (версия 3.2)

```text
Обнови существующий Marketing Metrics Bot с версии 3.1 до 3.2.
После расчета каждой из 12 метрик (ER, ERR, CTR, CPC, CPM, CR, CPA,
CPL, CAC, ROAS, ROMI, AOV) добавь блок
«📊 Как интерпретировать результат».
Объясняй практический смысл показателя и ограничения трактовки.
Не называй значение «хорошим» или «плохим» без отраслевого контекста,
целей или исторических данных. Не запрашивай дополнительные сведения
и не используй новые AI API. Сохрани формулы, историю, меню, анализ
кампаний, работу с отзывами и настройки Railway. Проверь синтаксис Python.
```

### Промпт 4. Проверка доработки

```text
Проверь обновленный bot.py: убедись, что все 12 метрик имеют блок
интерпретации, математические формулы не изменены, расчет сохраняется
в истории, а анализ рекламных кампаний и AI-анализ отзывов работают
по прежней логике. Укажи обнаруженные ошибки и предложи исправления.
```

**Что улучшить дальше:** добавить экспорт результатов, более подробную статистику использования и, при наличии исходных ориентиров, сравнение метрик с целями. Также полезно повторить пользовательское тестирование на большей выборке.

**Чему научились:** развертывать Python-бота в облаке, работать с переменными окружения и Volume, обновлять приложение через GitHub и превращать пользовательские замечания в конкретные доработки продукта.
